# Youtube-Stik production workspace

Original illustrated educational videos, planned around 20 minutes, with a hook no longer than five seconds. Target: one distinct episode per day after the pilot demonstrates capacity.

## Start here

1. Read [the SOP](YOUTUBE_PRODUCTION_TEAM_SOP.md).
2. Read [AI instructions](AGENTS.md), [project status](PROJECT_STATUS.md) and [approval log](APPROVAL_LOG.md).
3. Complete one authorised task, run QA, present the deliverable, and stop for Cristian's approval.

## Start a new AI session

> Read AGENTS.md, the full production SOP, PROJECT_STATUS.md, APPROVAL_LOG.md and DECISIONS_LOG.md from this repository. Verify the current repository state. Report the active task and existing approvals. If channel setup has not begun, prepare S01 only when I ask to begin. Do not start an episode or paid generation automatically. Every task requires QA and my approval before the next authorised step.

## Start setup

> Begin S01: prepare the channel brief using our SOP. Show the actual proposal and QA result or reviewer limitation. Stop for my approval.

## Start an episode after setup

> Propose a new episode about [idea]. Check channel setup dependencies, assign the next unused episode ID and prepare E01 only. Verify the premise, identify scope and preliminary sources, and stop for QA and my approval. Do not write the full script yet.

## Contents

- SOP and AGENTS.md: operating rules.
- PROJECT_STATUS.md: active state and next action.
- APPROVAL_LOG.md and DECISIONS_LOG.md: traceable decisions.
- templates/: task, episode, QA and approval templates.
- CHANGELOG.md: SOP changes.

This is a documented production workflow, not an installed autonomous production service. No paid tools, background jobs or publishing integrations are configured. GitHub stores instructions and records; generation, narration, editing and publishing need separately configured tools and approvals.

This repository is public. Keep confidential material and large media outside it in the storage selected during S05.
